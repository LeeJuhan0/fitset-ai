# 캐글 600k-programs → routines 변환 규약

`scripts/convert_kaggle_routines.py`가 캐글 600k-programs 데이터셋을
`routines` DynamoDB 테이블 스키마(→ [document-structure.md](document-structure.md) §1)에 맞는
S3 원본 JSON 문서로 변환한다.

- 원본: `programs_detailed_boostcamp_kaggle.csv` — **운동 1개 = 1행**, 프로그램별 연속 정렬 (약 253만 행)
- 변환 단위: 프로그램의 **(week, day) 세션 1개 = 루틴 문서 1개**
- 중복 제거: 같은 프로그램에서 운동 구성(운동명·세트·렙)이 동일한 세션은 첫 등장만 유지
  (주차 반복 프로그램이 대부분이라 세션의 60~70%가 제거됨)

```bash
python scripts/convert_kaggle_routines.py \
    --src ~/fitset-recsys-data/600k-programs/programs_detailed_boostcamp_kaggle.csv \
    --out routines.jsonl                  # 또는 --per-file <디렉토리> (S3 업로드용)
    # --exercise-map map.json             # 운동명→exercise_id 매핑 (없으면 null)
    # --limit 100                         # 테스트용
```

## 필드 매핑

| routines 필드 | 원본 컬럼 | 변환 규칙 |
|---|---|---|
| `_id` | title + week + day | `slugify(title)-w{week}-d{day}`, 충돌 시 `-2` 접미사 |
| `name` | title, week, day | `"{title} (Week {w} Day {d})"` |
| `description` | description | 그대로 |
| `exercises[]` | 세션의 행들 | CSV 등장 순서 = `order_index`. `sets` 수만큼 세트 배열 전개 |
| `exercises[].exercise_id` | exercise_name | `--exercise-map` 매핑 파일로 해석, 미매칭은 `null` (자동 매칭 16% — 수작업 매핑 필요) |
| `exercises[].sets[].weight` | (없음) | 항상 `null` — 원본에 무게 없음, 유저별 무게 추천이 채움 |
| `exercises[].sets[].reps` | reps | 양수 → int. **음수·0은 시간 기반(초) 인코딩 → `null`** (전체의 ~4.7%) |
| `level` | level (리스트) | 최소 요구 수준: Beginner·Novice→`beginner`, Intermediate→`intermediate`, Advanced→`advanced` |
| `equipment` | equipment (체육관 유형) | 유형→장비 목록 근사 (아래 표) |
| `goal` | goal (리스트) | 토큰별 매핑 후 다수결 (아래 표) |
| `muscle_groups` | exercise_name들 | 운동명 키워드 규칙으로 유도 (스크립트 `MUSCLE_PATTERNS`) |
| `minutes_per_routine` | time_per_workout | int 변환 |
| `created_at` / `updated_at` | created / last_edit | ISO 8601 (적재 배치가 덮어써도 무방) |

**버리는 원본 컬럼**: `program_length`(주 단위 프로그램 개념 제거), `intensity`(RPE — 스키마에 없음), `number_of_exercises`(파생값).

### equipment 매핑 (원본은 체육관 유형 1개 → 필요 장비 목록으로 근사)

| 원본 | 변환 |
|---|---|
| Full Gym | `["barbell","dumbbell","machine","cable","bench","rack","pullup_bar"]` |
| Garage Gym | `["barbell","dumbbell","bench","rack","pullup_bar"]` |
| Dumbbell Only | `["dumbbell"]` |
| At Home / 빈값 | `[]` (필요 장비 없음 → 모든 유저 통과) |

### goal 매핑 (토큰 8종 — 전수 확인, 다수결·동률 시 hypertrophy > strength > endurance)

| 원본 토큰 | 변환 |
|---|---|
| Bodybuilding, Muscle & Sculpting | `hypertrophy` |
| Powerlifting, Powerbuilding, Olympic Weightlifting | `strength` |
| Athletics, Bodyweight Fitness, At-Home & Calisthenics | `endurance` |

`weightLoss`는 원본에 대응 토큰이 없어 이 데이터셋에서는 생성되지 않는다.

## S3 적재 현황 · 2026-07-25 확정사항

### S3 원본 적재 완료

- 버킷: `s3://fitset-routines-raw` (ap-northeast-2, 계정 729743892772)
- `routines/{slug}.json` **98,818개** — (title, week, day) 세션 단위, **캐글 필드 원문 보존형**(운동명 원문, level/goal 문자열, reps 음수 포함, `source` 계보 블록). 제목 slug 충돌은 해시 6자리로 해소
- `source/` — 원본 CSV 2종 백업 (`programs_detailed_boostcamp_kaggle.csv` 281MB, `program_summary.csv`)
- 위 「필드 매핑」의 변환(enum 재매핑·운동명 해석)은 S3가 아니라 **S3 → DynamoDB `routines` 적재(변환 배치) 시점**에 수행한다. 매핑 보강 시 S3 재생성 없이 배치만 재실행 (PK=slug 멱등 PutItem)
- 적재 후 서빙: `scripts/load_routines_postgres.py`로 Postgres pgvector `routines`에 복사 → 서버는 룰 필터·코사인을 Postgres 쿼리 1건으로 (2026-08-28 전환, 종전 부팅 Scan 인메모리 방식은 폐기)

### 변환 배치: `scripts/load_routines_dynamodb.py` (2026-07-25 작성·적재 완료)

```bash
uv run --with boto3 python scripts/load_routines_dynamodb.py --dry-run   # 통계만
uv run --with boto3 python scripts/load_routines_dynamodb.py             # S3 → DynamoDB 전량
```

- DynamoDB 테이블: `routines` (ap-northeast-2, 온디맨드, PK=slug) — 2026-07-25 생성
- 정본 입력 (repo에 커밋):
  - `data/exercise-metadata.ko.json` — 종목 206종 마스터 (slug·`name_ko`·근육·장비)
  - `data/kaggle-exercise-alias.json` — 캐글 운동명 → slug alias 130개 (값 `null` = 의도적 드랍 11개)
- 종목 변환: alias → 휴리스틱(괄호 장비 전치·복수형 보정) 순으로 slug 해석,
  `exercise_name`=한글명(`name_ko`), `thumbnail_url`=`https://fitset-exercise-media.s3.ap-northeast-2.amazonaws.com/thumbnails/{slug}.webp`
- `equipment`/`muscle_groups`: 위 근사표 대신 **매칭된 종목 metadata 합집합**(서버 enum key) — 근사표는 폐기
- 전량 실측 (2026-07-25): 읽음 98,818 → **생존 67,787** (규칙 미달 19,964 · 주차 반복 중복 11,067),
  운동 행 유지 465,583/605,033 (77.0%)

### 임베딩 배치: `scripts/embed_routines.py` (2026-07-25)

```bash
uv run --with boto3 python scripts/embed_routines.py            # 미임베딩분만 (멱등)
uv run --with boto3 python scripts/embed_routines.py --force    # 모델 교체 시 전량 재계산
```

- 모델: Bedrock **`global.cohere.embed-v4:0`** (다국어, 서울 리전은 global inference profile로만 호출 가능 — `cohere.embed-v4:0` 직접 호출은 ValidationException)
- 임베딩 텍스트: 한글 종목명 나열 + description(영문, 2000자 절단) — 한/영 혼용은 다국어 모델이 흡수
- 저장: `routines.embedding` Binary(1024d float32 팩, 4KB) + `embedding_model` 버전 태그 — 태그가 같으면 스킵(멱등)
- 서빙: 임베딩은 Postgres `embedding vector(1024)` 컬럼 → 요청당 Bedrock 호출은 쿼리 임베딩 1회(`input_type=search_query`), 상위 30은 `ORDER BY embedding <=> query`

### exercise_id 확정 (협의 종결)

- **`exercise_id` = slug, `exercise_name` = 한글명(metadata `name_ko`)** — 백엔드 내부 API와 동일 체계 (2026-07-25 확정, uuid 미사용)
- `--exercise-map`은 「캐글 운동명 → slug」 alias 테이블로 사용하고, `exercise_name`은 slug로 metadata에서 한글명을 찾아 채운다

### 운동명 매칭 실측 (2026-07-25, distinct 3,213개 / 60.5만 행)

- 단순 slugify 1.8% → 괄호 장비 전치·복수형 보정 26.8% → **상위 130개 수동 alias 추가 시 행 기준 80.4%**
- 세션 생존(매핑 운동 ≥2개 & 원본 유지율 ≥60%, 미매칭 운동은 드랍): **78,854 / 98,818 (79.8%)**. 유지율 100%만 잡아도 33,632개
- alias 원칙: 비슷하면 206종 중 최근접 종목으로 매핑(장비 교차 허용), 아예 다르면 드랍(Cardio·Stretching·Run·Ab Wheel 등)
- reps 음수·0(시간 기반 인코딩)은 해당 운동 드랍

### 기존 규칙과의 정합성 주의 (스크립트 수정 필요)

- `equipment` 근사표의 `cable`·`bench`·`rack`·`pullup_bar`는 **서버 EQUIP enum에 없음** → 매핑된 종목들의 metadata `equipment` 합집합(서버 key: `cableMachine` 등)으로 전환 필요
- `muscle_groups` 키워드 규칙도 매핑된 종목들의 metadata `primaryMuscles` 합집합(소문자 서버 key)으로 대체 가능 — alias 매핑이 완성되면 키워드 추정보다 정확
