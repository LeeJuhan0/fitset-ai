# 코드 아키텍처

레이어드 + 도메인별 패키징.
의존 방향은 한 방향만: **router → service → (repository | clients | agent) → domain**

## 디렉토리 구조

```
app/
  main.py            # FastAPI 앱 조립, 라우터 등록
  deps.py            # 의존성 주입 (Bearer JWT 검증 → user_id, traceId)
  core/              # config, DynamoDB 커넥션, LLM 클라이언트(Bedrock), auth(JWT), errors(도메인 예외), handlers(전역 예외 핸들러), logging(설정·traceId 필터), 공통 응답 스키마(ApiResponse/CamelModel)
  clients/           # 외부 시스템 어댑터 (스프링 내부 API, S3) — 외부 경계는 여기서만
  chat/              # 채팅 도메인: POST /chat, 스레드·메시지·요약(스레드 압축 + 유저 장기) 관리
  routines/          # 루틴 도메인: 상세 API, 룰 필터 검색 + LLM 리랭킹
  exercises/         # 운동 도메인: 운동 마스터, GIF presigned URL 재발급
  agent/             # LangGraph: 그래프, 가드레일, 프롬프트, tools/
scripts/             # S3 → MongoDB 루틴 적재 배치 등
tests/
```

## 계층 규칙

- `router.py` — HTTP 입출력만. 비즈니스 로직·DB 접근 금지
- `schemas.py` — pydantic 요청/응답 모델만. `core/schemas.py`의 `CamelModel`을 상속(내부 snake_case ↔ 와이어 camelCase alias), 라우터는 `response_model=ApiResponse[모델]`(목록은 `ApiResponse[ListData[모델]]`)로 팀 규약 형식 `{traceId, data}`를 강제. 실패 `{traceId, error}`는 전역 예외 핸들러(main.py) 담당. 로직·I/O 금지
- `service.py` — 비즈니스 흐름. 언제/무엇을 읽고 쓸지 결정, 트랜잭션 경계 소유. `HTTPException` 대신 도메인 예외를 던지고 라우터가 HTTP로 번역
- `repository.py` — DB 명령이 사는 유일한 곳. commit/조합 판단 금지
- `domain.py` — I/O 없는 순수 함수·상수만 (예: 미요약 턴 판정, TTL 계산)
- `clients/` — 내가 소유하지 않은 시스템(스프링 API, S3)은 얇은 클라이언트로 감싼다. 테스트 모킹 지점
- 스프링 DB에 직접 붙는 코드는 어디에도 없다 — 사용자 데이터는 반드시 스프링 내부 API 경유

## 데이터 규칙 (요약)

- payload에는 식별자만 저장(exercise_id, slug) — URL·미디어는 클라가 조회 시점에 획득
- 시각은 BSON datetime, `_id`(objectid) 내장 시각을 정렬 기준으로 겸용
- TTL은 `chat_threads.last_message_at`에만 — 만료 시 스레드 문서만 삭제되므로 고아 메시지는 일 1회 배치 정리
- 요약 갱신은 응답 후 BackgroundTasks (n턴 도달 시, 스레드 압축·유저 요약 증분 병합)
