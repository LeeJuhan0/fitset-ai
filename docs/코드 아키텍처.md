# 코드 아키텍처

레이어드 구조와 도메인별 패키징. 의존은 한 방향.

```
router -> service -> repository, clients, agent -> utils, models, enums
```

## 디렉토리 구조

```
app/
  main.py        # 앱 조립, 미들웨어, lifespan, 헬스체크
  deps.py        # 요청 단위 주입, traceId
  core/          # 도메인 무관 공통
    config.py    #   환경변수 설정
    dynamo.py    #   DynamoDB 모델 베이스, 테이블 바인딩
    orm.py       #   SQLAlchemy 선언 베이스 2종
    clock.py     #   UTC 시각, Z 접미 표기
    ulid.py      #   시간순 ULID 채번
    ratelimit.py #   토큰버킷 클래스, 인스턴스는 각 도메인 service
    exceptions.py#   예외 베이스, 공통 예외
    handlers.py  #   전역 예외 핸들러
    logging.py   #   로깅, traceId 필터
    schemas.py   #   공통 응답 스키마
  clients/       # 외부 시스템 클라이언트 (DB, Bedrock)
    mysql.py     #   백엔드 MySQL 읽기 전용
    postgres.py  #   루틴 검색 Postgres 읽기 전용
    bedrock.py   #   Bedrock LLM, 임베딩
  auth/          # JWT RS256 검증, SSM 공개키, 현재 유저 의존성
  chat/          # 스레드, 메시지 SSE(sse.py 프레임, 하트비트), 스레드 압축 요약
  memory/        # 유저 장기 요약, 성격 이력
  users/         # 프로필, 기피 부위, 체중
  workouts/      # 세션, 종목, 세트 기록
  routines/      # 루틴 추천 유스케이스, 무게 산출, 응답 조립
  rag/           # 루틴 검색 파이프라인
    query.py     #   ① 요청 분석 (구조화 출력, 묘사문 기피 부위 안전 제약)
    embed.py     #   ② 묘사문 쿼리 임베딩
    retrieve.py  #   ③ 룰 필터 WHERE + pgvector 코사인 상위 K, 문맥 기피 재시도
    rerank.py    #   ④ 랜덤 샘플 + LLM 최종 선택, 실패 시 코사인 1위
    pipeline.py  #   ②~④ 조립
    prompts.py   #   분석과 선택 프롬프트, 구조화 출력 스키마
  exercises/     # 종목 카탈로그, 마스터, 영상 URL
  charts/        # 지표별 조회, 집계
  agent/         # LangGraph 챗봇
    tools/       #   차트, 루틴, 종목 가이드, 기록 조회
scripts/         # 배치, 적재, 임베딩, 로컬 실행
tests/
data/            # 종목 메타데이터 206종
docs/
```

도메인 패키지는 router, schemas, service, utils, enums, models, repository, exceptions 중 필요한 것만 둔다. ml-server 와 같은 내부 계층이다.

## 패키지별 저장소와 엔티티

| 패키지 | 저장소 | 엔티티 |
|---|---|---|
| `chat` | DynamoDB 2테이블, PynamoDB | `ThreadRecord`, `MessageRecord` |
| `memory` | DynamoDB `user_summaries`, PynamoDB | `UserSummaryRecord` |
| `users` | 백엔드 MySQL 직조회 | `UserProfile`, `UserAvoidedMuscle`, `BodyWeightHistory` |
| `workouts` | 백엔드 MySQL 직조회 | `WorkoutHistory`, `WorkoutHistoryExercise`, `WorkoutHistorySet` |
| `routines` | Postgres pgvector (검색은 `rag`) | `Routine` |
| `exercises` | DynamoDB 카탈로그, MySQL 마스터, 동봉 JSON | `Exercise`, `Equipment`, `Muscle`, `ExerciseMuscle`, `CatalogEntry` |
| `charts` | 없음, users와 workouts 조회 | 없음 |
| `agent` | Bedrock, MySQL 기록 조회 | `AgentResult`, `GraphEvent` |
| `clients` | 엔진 싱글턴, 커넥션 풀, READ ONLY | 없음 |
| `core` | 공통 베이스와 클라이언트 | 공통 응답 스키마 |

## 계층 규칙

| 파일 | 역할 | 금지 | 스프링 대응 |
|---|---|---|---|
| `router.py` | HTTP 입출력 | 비즈니스 로직, DB 접근 | `@RestController` |
| `schemas.py` | 요청 응답 모델, camelCase 변환 | 로직, I/O | DTO |
| `service.py` | 비즈니스 흐름, `if` 가드 절에서 도메인 예외 raise | `HTTPException` 직접 생성, 폴백용 try | `@Service` |
| `repository.py` | DB 명령 전담 | 조합 판단 | `@Repository` |
| `utils.py` | 순수 함수, 상수 | I/O, 전역 상태 | 도메인 서비스 |
| `enums.py` | 상태, 구분값 StrEnum | 로직 | `enum` |
| `models.py` | 엔티티, PynamoDB 레코드 | I/O 호출 | `@Entity` |
| `exceptions.py` | 도메인 예외 선언, `DomainError(HTTPException)` 하위, `__init__` 에서 `super().__init__` 으로 상태코드와 code message 고정 | 로직, 중복 선언 | `BusinessException` |
| `clients/` | 외부 저장소 어댑터, 표기 변환 | 비즈니스 판단 | DataSource, 어댑터 |
| `core/` | 공통 인프라 | 도메인 지식 | config, `@ControllerAdvice` |

1. 엔티티는 각 패키지 `models.py` 소유. 선언 베이스만 `core/orm` 공유.
2. VO 계층 없음. 필요 시 pydantic, dataclass.
3. 커서 없는 목록은 `ItemsData`. 채팅 API는 `page` 미사용.
4. 유저 데이터는 MySQL 직조회. `clients/mysql.py` 경유 필수. 쓰기 없음.
5. 둘 이상 패키지가 쓰는 예외는 `core/exceptions`.

## 의존성 주입

기준은 수명. 요청 단위는 Depends, 프로세스 단위는 싱글턴.

| 자원 | 방식 | 테스트 교체 |
|---|---|---|
| user_id, traceId | FastAPI Depends | `dependency_overrides` |
| 설정, LLM, 엔진, 그래프, 리미터 | `lru_cache` 싱글턴 | monkeypatch, `cache_clear` |
| DynamoDB 커넥션 | PynamoDB 모델 캐시 | moto `mock_aws`, `bind_tables` |

## 운영 규칙

1. `/health`는 프로세스 생존만 확인. 의존 저장소 미포함.
2. CORS 미설정. 호출자는 네이티브 앱, 브라우저는 동일 출처.
3. 종료 시 Postgres 풀 정리. lifespan 담당.

## 데이터 규칙

1. payload는 식별자만 저장. slug, exerciseId.
2. 시각은 Z 접미 ISO 문자열. DTO도 str.
3. 식별자는 ULID. SK 정렬 겸용.
4. TTL은 `chat_threads.expires_at`만. 고아 메시지는 일 1회 배치 정리.
5. 요약 갱신은 응답 후 BackgroundTasks.
