# 배포 가이드

AI 서버가 dev 환경에 어떻게 올라가는지 정리한다. 인프라 정본은
https://github.com/asm-hangang/fitset-infra-tf 이고 여기서는 AI 서버 관점만 다룬다.

2026-09-21 에 EKS·ArgoCD 를 걷어내고 EC2 + docker compose 로 옮겼다.

## 경계

| 주체 | 책임 |
| --- | --- |
| 이 레포 `.github/workflows/cd.yml` | 이미지 빌드·ECR push, SSM 으로 배포 명령 |
| `s3://fitset-deploy-artifacts/dev/ai-compose/` | `docker-compose.yml` · `up.sh` — 무엇을 어떻게 띄울지 |
| fitset-infra-tf | EC2 · ALB · 보안그룹 · IAM · RDS · DynamoDB |

## 흐름

```
develop 머지
  → CD 가 이미지를 ECR 에 push (태그 = 커밋 SHA)
  → SSM SendCommand 로 EC2 의 /opt/fitset 을 S3 에서 동기화하고 up.sh 실행
  → 박스 안에서 localhost:8000/health 확인
  → ALB 를 통해 https://api-dev.fitset.kro.kr/ai/v1/health 확인
```

배포 대상은 전용 인스턴스다(백엔드와 한 대를 쓰지 않는다 — 2GiB 에 JVM 과
파이썬 런타임을 같이 두면 서로의 여유를 깎는다). ALB 는 백엔드와 공유하고
**경로로 갈린다** — 라우터가 전부 `/ai/v1` 접두어라 `/ai/*` 규칙 하나면 된다.

## 설정 주입

| 종류 | 어디에 | 예 |
| --- | --- | --- |
| 평문 env | `dev/ai-compose/docker-compose.yml` | `CHAT_THREADS_TABLE`, `JWT_PUBLIC_KEY_PARAM` |
| 비밀값 | SSM SecureString → `up.sh` 가 프로세스 환경으로만 넘긴다 | `/fitset/dev/pg/password`, `/fitset/dev/ai/mysql-password` |
| 엔드포인트 | `up.sh` 의 export | `PG_HOST`, `MYSQL_HOST` |

비밀값은 디스크에 쓰지 않는다. `up.sh` 가 `aws ssm get-parameter` 로 읽어
compose 프로세스 환경으로만 넘긴다. **`--output text` 는 쓰지 않는다** —
여러 줄 값(PEM 등)의 줄바꿈이 뭉개진다.

## 접속·디버깅

```bash
aws ssm start-session --target <instance-id>     # 22번은 열려 있지 않다
docker logs --tail 100 fitset-ai
docker compose -f /opt/fitset/docker-compose.yml ps
```

인스턴스 ID 는 fitset-infra-tf 의 `ai_instance_id` 출력값이고, CD 워크플로의
`INSTANCE_ID` 와 같아야 한다.

## 되돌리기

ECR 태그가 커밋 SHA 라 되돌릴 대상이 분명하다. 박스에서 `/opt/fitset/image` 에
옛 SHA 를 적고 `up.sh` 를 다시 돌리면 그 이미지로 돌아간다.
