# 무게 추천 로직 (2026-07-25 확정, 2026-08-18 B·C 계층 개정)

AI 루틴 생성 시 세트 `weight`를 채우는 규칙. 루틴 템플릿의 weight는 항상 `null`이며
유저별 추천값이 덮어쓴다. 맨몸(`bodyweight`) 종목은 항상 `null`.

입력: 프로필(성별·체중·`level`·`goal`) + 최근 운동기록 — 출처는 백엔드 DB 직조회(2026-08-12 내부 API 파기), 루틴 템플릿의 목표 렙(`target_reps`),
종목 metadata(`primaryMuscles`·`movementPattern`·`equipment`).

## 3계층 폴백

### A. 해당 종목 기록 있음 — 실측 e1RM 기반

```
e1RM       = weight × (1 + reps/30)          # Epley — 기록 세트별 계산, 기간 내 최대값
추천무게    = e1RM / (1 + target_reps/30)     # 목표 렙으로 역산
진행(선택)  = 직전 세션에서 목표 렙 전부 성공 시 × 1.025   # 미구현
```

- `weight = 0`인 세트는 제외 (백엔드 `workout_set.weight_kg`가 NOT NULL default 0 — 맨몸/미기록 인코딩)
- reps > 12인 세트는 Epley 오차가 커지므로 e1RM 계산에서 제외 (12렙 이하 세트만 사용)
- 실측 기반이므로 level·goal 보정 불필요
- 유저가 실제로 든 무게이므로 상한을 걸지 않는다

### B. 해당 종목 기록 없음, 같은 전이 키 기록 있음

전이 키는 `(주동근, 패턴 그룹, 장비)` 세 값이 모두 같은 조합이다. 이 중 최대 e1RM에 종목 간 전이 안전 계수 0.8을 곱하고, C 계층 초기 추정의 3배를 상한으로 자른 뒤 목표 렙으로 역산한다.

주동근만으로 묶으면 두 가지 경로로 불가능한 무게가 나간다. 2026-08-13 실기기 검증 26건에서 팔 고립 종목에 60~82.5kg이 나온 원인이다.

| 누수 경로 | 예시 | 막는 축 |
|---|---|---|
| 복합 → 고립 | 머신 언더핸드 로우(이두 주동)의 e1RM이 덤벨 컬로 | 패턴 그룹 |
| 캐리 → 고립 | 케틀벨 파머스 캐리(전완 주동)가 리스트 컬로 | 패턴 그룹 |
| 양손 → 한 손 | 바벨 벤치 e1RM이 덤벨 벤치 한 손 무게로 | 장비 |

상한은 최후 방어선이다. 전이 키가 같아도 종목별 절대 부하 차이는 남으므로, 사람 기준(체중·성별·수준·목표)으로 계산한 C 계층 값의 3배를 넘는 e1RM은 쓰지 않는다.

### C. 기록 전무 — 성별·체중·레벨·목표 기반 초기값

```
초기 e1RM = 체중(kg) × 패턴 비율 × 레벨 계수 × 목표 계수 × 장비 계수
            (덤벨·케틀벨은 한 손 표기라 ÷2)
추천무게  = 초기 e1RM / (1 + target_reps/30)
```

패턴 비율 (metadata `movementPattern`으로 그룹핑, 초급 스탠다드 하단):

| 패턴 그룹 | 남 | 여 | 비고 |
|---|---|---|---|
| 스쿼트 계열 | 0.70 | 0.55 | |
| 힌지(데드리프트 계열) | 0.90 | 0.68 | |
| 수평 푸시(벤치 계열) | 0.55 | 0.32 | |
| 수직 푸시(오버헤드 계열) | 0.38 | 0.23 | |
| 로우/풀 계열 | 0.50 | 0.35 | |
| 고립 | 0.30 | 0.20 | 컬·레그 익스텐션·카프 레이즈 등 |
| 작은 근육 고립 | 0.20 | 0.13 | 주동근이 어깨·전완·삼두인 레이즈·리스트 컬 계열 |

장비 계수 (metadata `equipment`):

| 장비 | 계수 | 한 손 환산 | 근거 |
|---|---|---|---|
| 바벨 | 1.00 | | 패턴 비율의 기준 |
| 머신 | 1.15 | | 궤도가 고정돼 안정화 부담이 없다. 1.10은 5kg 반올림에 묻혀 바벨과 같은 값이 된다 |
| 케이블 | 0.85 | | 상시 장력이라 같은 동작에서 덜 든다 |
| 덤벨 | 0.85 | ÷2 | 좌우를 따로 잡느라 안정화에 힘을 쓴다 |
| 케틀벨 | 0.80 | ÷2 | 무게 중심이 손 바깥이라 같은 무게도 덤벨보다 어렵다 |

계수와 한 손 환산은 이유가 다르다. 계수는 같은 동작이라도 기구에 따라 실제로 들 수 있는 부하가 다르다는 것이고, 환산은 덤벨·케틀벨의 표기 무게가 기구 한 개 기준이라는 단위 문제다. 환산하지 않으면 바벨 총부하가 한 손 무게로 그대로 붙어 두 배가 된다.

추천 결과의 `weight`도 기구 한 개 기준으로 나간다. 덤벨 14kg은 14kg짜리 두 개를 드는 것이다(클라이언트 API 명세 §1).

한 손이냐 양손이냐는 원래 종목의 성질인데 카탈로그에 그 필드가 없어서 장비로 근사한다. 덤벨·케틀벨 79종목 중 고블릿 계열 6종목과 케틀벨 스윙·파머스 캐리·스러스터, 덤벨 싯업·사이드 벤드·러시안 트위스트 등 15종목은 하나를 두 손으로 드는데 절반 환산이 걸려 실제보다 가볍게 나온다. 오차는 한 방향뿐이다 — 한 손 종목을 양손으로 오인해 무겁게 주는 경우는 없다.

2026-08-18 개정 전 값은 스쿼트 0.50, 힌지 0.60, 수평 푸시 0.35, 수직 푸시 0.25, 풀 0.35, 고립 0.10이었다. 70kg 남성 초급 기준으로 바벨 31종목 중 22종목이 봉 무게 20kg보다 가벼운 값을 내서, 만들 수 없는 세트가 그대로 나갔다.

레벨 계수 (프로필 `level` — DIFFICULTY enum. 요청 `level`은 쓰지 않는다. 요청 난이도는 이번 세션을 얼마나 세게 할지의 선택이지 그 사람의 근력이 바뀐 것이 아니라서, 요청 값을 쓰면 고급을 고를 때마다 무게가 1.6배가 된다):

| level | 계수 | 근거 |
|---|---|---|
| `beginner` | 1.0 | 기준값 (novice 스탠다드) |
| `intermediate` | 1.3 | 스탠다드상 novice→intermediate 격차 ~1.25–1.4배 |
| `advanced` | 1.6 | intermediate 대비 ~1.25배 추가 |

목표 계수 (프로필 `goal` — GOAL enum. 요청 필드가 아니다, 2026-07-29 확정):

| goal | 계수 | 비고 |
|---|---|---|
| `strength` | 1.1 | 고강도 지향 — 초기값 상향 |
| `hypertrophy` | 1.0 | 기준 |
| `weightLoss` · `endurance` | 0.9 | 볼륨·지속 지향 — 하향 |

- 주 강도 조절은 목표 렙 역산이 담당하고, 목표 계수는 보정만 한다 (렙 수가 같아도 목표별 체감 강도 차이 반영).
- 프로필 `level`·`goal`이 `null`이면 각각 `beginner`·`hypertrophy`로 간주 (기본값 처리는 AI 서버 책임 — 구 내부 API 규약 승계. ERD상 컬럼은 NOT NULL이라 null은 프로필 미생성 케이스).

## 공통 마무리 규칙

1. **장비별 반올림**: 바벨 5kg(원판 2.5kg 한 쌍이 최소 증분) / 덤벨·케틀벨 2kg / 머신·케이블 5kg 단위 (밴드는 무게 개념 없음 → `null`)
2. **장비별 최소 무게**: 바벨 20kg(올림픽 봉) / 덤벨 2kg / 케틀벨 4kg / 머신·케이블 5kg. 계산 결과가 이보다 작으면 최소 무게로 올린다. 봉을 쓰지 않거나 봉이 가벼운 종목은 슬러그 단위 예외를 둔다 — EZ바 10kg, 랜드마인 10kg, 플레이트 5kg. 워밍업 세트도 같은 하한을 지킨다
3. **강도 존 클램프**(미구현): 최종 %1RM( = 추천무게 ÷ e1RM)이 NSCA 존을 크게 벗어나면 경계로 조정
   — 근력 85%↑(1–6렙) · 근비대 67–85%(6–12렙) · 지구력 67%↓(12렙↑).
   Epley 역산이 렙 수에 맞는 %1RM을 내주기 때문에 존을 크게 벗어나는 경우가 드물어 미룬 상태다(6렙 83.3%, 12렙 71.4%, 20렙 60%)
4. **워밍업 세트**(`includeWarmup`): 해당 종목 첫 세트를 본 세트 무게 × 0.5로 경량화
5. **설계 원칙 — 낮게 시작해서 빠르게 올린다**: 초기값 오차 비용은 비대칭(과중량 = 부상·이탈, 경량 = 다음 세션 +2.5%로 회복). 모든 추정 계층은 보수 편향.

전부 `app/routines/domain.py`이고, 세트 조립과 워밍업 적용은 `app/routines/service.py`의 `_build_set`·`_build_response`가 호출한다.

## 미구현·남은 문제

1. A 계층 진행 규칙(×1.025)과 강도 존 클램프가 코드에 없다.
2. 한 손·양손 구분을 장비로 근사한다. 카탈로그에 `unilateral` 같은 필드가 생기면 `PER_HAND_EQUIPMENT`를 걷어낸다.
3. 케이블 계수 0.85는 대략의 보정이다. 도르래 비율 때문에 스택 표기 무게가 실제 부하와 달라서, 물리적으로 정확한 값이 아니다.
4. 한 팔 덤벨 로우는 몸을 지지하고 하는 동작이라 다른 덤벨 종목보다 무겁게 들 수 있는데, 지금은 같은 계수를 받는다. 2번 필드가 생기면 같이 정리한다.
5. A 계층에 상한이 없어서, 앱이 완료 기록에 추천 무게를 그대로 쓴다면 그 값을 다시 읽어 무게가 계속 올라가는 되먹임이 생긴다. 클라 기록 규칙 확인이 필요하다.
6. 고립 그룹이 컬과 레그 익스텐션을 한데 묶는다. 절대 부하 차이가 큰 만큼 주동근 단위로 더 잘게 나눌 여지가 있다.
7. 무게 로직이 아니라 종목 선정 문제로 남는 것 — 초급에게 바벨 리스트 컬처럼 빈 봉이 이미 과한 종목이 배정되는 경우. 조립층에서 다룬다.

## 근거

- Epley 공식: 1RM 추정의 사실상 표준 (reps ≤ 10–12 구간에서 정확)
- 강도 존: NSCA/ACSM 트레이닝 가이드라인
- 체중 비율 스탠다드: strengthlevel 계열 집계. 2026-08-18 개정에서 초급 대역 하단으로 올렸다 — 그 전 novice 보수치는 빈 봉보다 가벼운 값을 냈다
- 구 recsys 설계의 `exercise_one_rm` 테이블은 새 백엔드 ERD에서 제외됨 → 1RM은 저장하지 않고 AI 서버가 요청 시 기록에서 계산
